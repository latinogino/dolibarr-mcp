# Changelog

All notable changes to the Dolibarr MCP Server are documented here. The project
follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html) and adopts the
[Keep a Changelog](https://keepachangelog.com/en/1.0.0/) format.

## [Unreleased]

### Added
- Ticket management tools: `get_tickets` (open tickets by default, optional status filter), `get_ticket_by_ref`, `search_tickets`, `create_ticket`, `add_ticket_message` and `update_ticket`. Tickets are addressed by their `ref`; `add_ticket_message` and `update_ticket` resolve it to the `track_id` / numeric id. Contributed by Guenter Lukas (latinogino/dolibarr-mcp#28).

### Fixed
- `get_projects` returned an empty list and `get_users` / `get_customers` skipped the second page: Dolibarr pages start at 0, tool pages start at 1. Reported by Guenter Lukas (latinogino/dolibarr-mcp#30).

## [1.3.0] - 2026-11-25

### Added
- `get_documents` tool: list the files attached to an object (invoice, order, proposal, third party...) by ref or id, with the `original_file` path expected by `download_document`.
- `download_document` tool: return a file as an embedded resource (10 MB limit) and extract the files embedded in a PDF, such as the Factur-X `factur-x.xml`, as text. `include_file: false` returns only metadata and the extracted files. Adds the `pypdf` dependency.
- `get_invoices`: `customer_id` filter, `page`, `sort_by` (`date` / `ref` / `id`) and `sort_order`. Newest first by default; `limit` defaults to 20 and is capped at 200.
- `update_invoice`: `cond_reglement_id` (payment terms) and `mode_reglement_id` (payment method).

### Changed
- `get_invoices` returns a compact summary per invoice (ref, dates, totals, status, remaining amount, project) instead of the raw Dolibarr objects; `full: true` restores the raw output. Dates are reported in local time, as stored by Dolibarr. An empty filtered list returns `[]` instead of an error.
- 5xx errors now carry Dolibarr's own error message and the real HTTP status.

### Fixed
- Invoice lines were booked at 0% VAT: the `vat` field of `add_invoice_line`, `update_invoice_line` and `create_invoice` is now sent as Dolibarr's `tva_tx`.
- `update_invoice_line` no longer resets the fields that are not given (Dolibarr's PUT overwrites the whole line): the current line is read and merged before the update.
- `add_invoice_line` returns the new line id when Dolibarr answers 5xx although the line was inserted, so that callers do not retry and create duplicates.
- Search tools now find names containing an apostrophe (straight or typographic): Dolibarr's `sqlfilters` cannot match a literal apostrophe, so it is replaced by the `_` wildcard.
- `create_customer` no longer fails when a third-party code numbering module is enabled: `code_client` / `code_fournisseur` are sent as `-1` (generated by Dolibarr) unless given explicitly.
- Replaced the deprecated `datetime.utcnow()`.
- `test_config_from_dotenv` failed when a `.env` file existed in the working directory.

## [1.2.0] - Security hardening

### Security
- Bearer token authentication for the HTTP transport (`MCP_HTTP_TOKEN`); refuses to listen on a non-loopback interface without it.
- HTTP listener binds `127.0.0.1` by default; Docker Compose publishes on `127.0.0.1` and requires `MCP_HTTP_TOKEN`.
- CORS wildcard removed; origins must be allow-listed via `MCP_CORS_ORIGINS`.
- `MCP_READ_ONLY` mode hiding and rejecting every write tool.
- `dolibarr_raw_api` disabled by default (`MCP_ENABLE_RAW_API`).

### Fixed
- Pinned dependencies: `mcp>=1.0.0` now resolves to mcp 2.x, which breaks the server; constrained to `mcp<2` and pinned tested versions in `requirements.txt`. Minimum Python is now 3.10.
- `get_status` / `test_connection` called `/api/status` (404) instead of `/api/index.php/status`.
- Tool errors (policy refusals, Dolibarr API errors, internal errors) are now returned with `isError: true`.
- Single version source (`dolibarr_mcp.__version__`) reported over both stdio and HTTP transports; removed unused `MCP_SERVER_NAME` / `MCP_SERVER_VERSION` from Docker Compose.

### Added
- Restored README.md and CHANGELOG.md after merge conflicts while preserving the streamlined structure shared with `prestashop-mcp`.
- Documented platform-specific setup covering Linux/macOS shells, Windows Visual Studio `vsenv`, and the Docker workflow.

### Changed
- Reconciled feature and tool descriptions so they capture both the detailed ERP coverage and the new documentation bundle layout.
- Clarified configuration guidance around `pydantic-settings`, environment variables, and `.env` files.

### Removed
- Obsolete references to legacy helper scripts and superseded documentation variants that were dropped during the repository cleanup.
